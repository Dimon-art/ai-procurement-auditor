# Exclusive Summary — AI Procurement Auditor

Краткий итоговый документ для передачи преподавателю.

## 1. Что создано?

Учебный MVP веб-приложения **AI Procurement Auditor** на Django для первичной проверки закупочных/бухгалтерских документов.

Реализованы:

- веб-интерфейс (вход, регистрация, список, загрузка, карточка документа);
- загрузка файла и OCR;
- извлечение реквизитов и позиций;
- Rule Engine с 10 проверками;
- расчёт оценки риска и итогового решения;
- изоляция данных по компании пользователя;
- Docker-сборка для production-запуска.

## 2. Зачем создано?

Чтобы автоматизировать первичную обработку документа и показать преподавателю рабочий сценарий:

загрузка → распознавание → проверки → риск → понятный результат.

Проект не претендует на замену бухгалтерской экспертизы.

## 3. Что уже работает?

- авторизация и регистрация;
- список документов и сводные счётчики (всего / требуют внимания / высокий риск);
- загрузка и обработка документа;
- карточка документа: реквизиты, позиции, проверки, оценка риска;
- API-часть проекта (DRF) и аудит действий в объёме текущего кода;
- `manage.py check` проходит;
- ключевые тесты карточки (`DocumentDetailPageUITests`) проходят.

## 4. Как устроен проект?

Основные приложения в `apps/`:

- `documents` — документы, OCR, поля, позиции, HTML UI;
- `rules` — правила, score, decision;
- `users` / `companies` — пользователи и компании;
- `suppliers` — справочник поставщиков;
- `audit` — журнал действий.

Конфигурация Django — в `config/`.  
Документация — в `docs/`, а также `README.md` и `BRIEF.md`.

## 5. Как проверить основной сценарий?

1. Запустить проект локально (`migrate` + `runserver`) или открыть production URL после деплоя.  
2. Войти или зарегистрироваться.  
3. Открыть список документов.  
4. Загрузить документ.  
5. Открыть карточку.  
6. Проверить реквизиты, позиции, проверки и оценку риска.

Подробная инструкция — в `README.md`.

## 6. Что проверяет система?

1. Проверка формата файла  
2. Проверка целостности файла  
3. Проверка качества OCR  
4. Проверка обязательных полей  
5. Проверка поставщика  
6. Проверка дубликата файла  
7. Проверка дубликата документа  
8. Проверка суммы  
9. Проверка даты  
10. Проверка НДС  

## 7. Как рассчитывается риск?

1. Для каждой проверки сохраняется результат с баллом (`score`).  
2. `calculate_risk_score(document)` суммирует баллы **последних** результатов по каждому правилу.  
3. `determine_document_decision(risk_score)` определяет итог:

| Оценка риска | Решение |
|---|---|
| 0 | без существенных рисков (`ok`) |
| 1–20 | требует внимания (`warning`) |
| 21–60 | высокий риск (`risk`) |
| 61+ | высокий риск / ручная проверка (`manual_review`) |

В пользовательском интерфейсе решения `risk` и `manual_review` отображаются как высокий риск.

## 8. Какие ограничения есть?

- это MVP;
- OCR зависит от качества файла;
- не все реквизиты УПД и других форм извлекаются;
- позиции извлекаются не всегда;
- набор правил фиксированный;
- нет заявления о поддержке полного списка первичных документов;
- система не заменяет эксперта-бухгалтера.

## 9. Что можно улучшить дальше?

- более полное извлечение реквизитов;
