# AI Procurement Auditor

Веб-приложение на Django для автоматической проверки закупочных и бухгалтерских документов. Система принимает файлы, выполняет OCR, извлекает реквизиты, проверяет документ по набору правил и формирует оценку риска с понятным результатом для бухгалтера.

Учебный MVP с рабочим backend, REST API и базовым веб-интерфейсом.

---

## Основные возможности

Реализовано в текущей версии проекта:

- **Публичные страницы:** главная (`/`), вход (`/login/`), регистрация (`/register/`)
- **Работа с документами через браузер:**
  - список документов компании (`/documents/`)
  - загрузка файла (`/documents/upload/`)
  - просмотр результата проверки (`/documents/<id>/`)
  - ручное утверждение документа
- **OCR и pipeline обработки:**
  - распознавание текста документа
  - извлечение полей и строк документа
  - запуск Rule Engine
  - расчёт `risk_score` и итогового `decision`
- **Rule Engine:** 10 бизнес-правил (R001–R010) — формат файла, целостность, качество OCR, обязательные поля, поставщик, дубликаты, суммы, даты, НДС
- **REST API** с JWT-аутентификацией: документы, компании, поставщики, pipeline, отчёты, audit log, профиль пользователя
- **Django Admin** для управления справочниками и данными
- **Health-check** (`/health/`) для проверки доступности приложения и базы данных
- **Audit log** — фиксация действий пользователей (например, утверждение документа)

Поддерживаемые форматы загрузки: **PDF, PNG, JPG/JPEG** (до **15 МБ**).

## Используемые технологии

- **Python 3**
- **Django 5.2**
- **Django REST Framework**
- **djangorestframework-simplejwt** — JWT-аутентификация API
- **SQLite** — база данных по умолчанию
- **WhiteNoise** — раздача статических файлов
- **python-dotenv** — переменные окружения
- **requests** — HTTP-запросы (OCR Yandex)
- **Gunicorn** — WSGI-сервер (для деплоя)

OCR-провайдеры (настраиваются через `OCR_PROVIDER`):

- `yandex` — Yandex Vision OCR (требуются переменные окружения)
- `mock` — заглушка для локальной разработки и тестов

## Структура приложений

```text
ai-procurement-auditor/
├── apps/
│   ├── companies/     # Компании
│   ├── suppliers/     # Справочник поставщиков
│   ├── users/         # Профили пользователей, регистрация, API профиля
│   ├── documents/     # Документы, OCR, pipeline, веб-интерфейс, API
│   ├── rules/         # Rule Engine, CheckResult, risk score, decision
│   └── audit/         # Журнал аудита
├── config/            # Настройки Django, URL, health-check
├── docs/              # Архитектурная и проектная документация
├── manage.py
└── requirements.txt
```

| Приложение | Назначение |
|------------|------------|
| `companies` | Модель компании, API списка компаний |
| `suppliers` | Поставщики компании, API |
| `users` | `UserProfile` (компания, роль, статус), регистрация, вход, API `/api/v1/users/me/` |
| `documents` | Загрузка и хранение документов, OCR, извлечение полей, pipeline, веб-страницы и API |
| `rules` | Правила проверки, результаты проверок, расчёт риска |
| `audit` | Журнал действий пользователей |

## Установка и локальный запуск

### 1. Клонировать репозиторий

```bash
git clone <url-репозитория>
cd ai-procurement-auditor
```

### 2. Создать и активировать виртуальное окружение

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate

# Linux / macOS
source .venv/bin/activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Настроить переменные окружения

Создайте файл `.env` в корне проекта. Минимально необходимые переменные:

```env
SECRET_KEY=your-secret-key-here
DEBUG=True
```

Дополнительно для OCR Yandex (если используется провайдер `yandex`):

```env
OCR_PROVIDER=yandex
YANDEX_OCR_API_KEY=
YANDEX_FOLDER_ID=
```

Для локальной разработки без внешнего OCR:

```env
OCR_PROVIDER=mock
```

> Не храните реальные секреты в репозитории. Файл `.env` должен быть добавлен в `.gitignore`.

### 5. Применить миграции

```bash
python manage.py migrate
```

### 6. Создать администратора

```bash
python manage.py createsuperuser
```

### 7. Запустить сервер разработки

```bash
python manage.py runserver
```

Приложение будет доступно по адресу: `http://127.0.0.1:8000/`

## Сценарий работы обычного пользователя

1. **Регистрация** — открыть `/register/`, указать имя пользователя, e-mail и пароль.
2. **Вход** — перейти на `/login/` и авторизоваться. После входа выполняется переход на `/documents/`.
3. **Назначение профиля** — для доступа к документам у пользователя должен быть создан `UserProfile` с привязкой к компании. Это выполняет администратор через `/admin/` (см. сценарий администратора).
4. **Загрузка документа** — открыть `/documents/upload/`, выбрать компанию и файл (PDF/PNG/JPG).
5. **Просмотр результата** — система выполняет OCR, извлечение полей и проверку по правилам. На странице документа отображаются:
   - статус обработки
   - оценка риска
   - список выявленных проблем
   - основные реквизиты
6. **Принятие решения** — бухгалтер изучает результат и при необходимости утверждает документ кнопкой «Утвердить документ».

---

## Сценарий работы администратора

1. **Вход в Django Admin** — `/admin/` под учётной записью с правами `staff` / `superuser`.
2. **Настройка компании** — создать или проверить запись компании в разделе `Companies`.
3. **Настройка поставщиков** — добавить поставщиков компании в разделе `Suppliers` (используется правилом проверки поставщика).
4. **Назначение пользователю профиля** — в разделе `User profiles` создать профиль: привязать пользователя к компании, указать ФИО, роль и статус `active`.
5. **Контроль документов** — просматривать загруженные документы, результаты OCR и проверок через Admin или через API.
6. **Мониторинг** — проверять `/health/` и журнал аудита при необходимости.
