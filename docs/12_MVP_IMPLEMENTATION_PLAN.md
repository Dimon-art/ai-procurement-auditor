# AI Procurement Auditor

**Документ:** MVP Implementation Plan  
**Версия:** 1.0  
**Статус:** Draft  
**Автор:** Solution Architect / Staff LLM Engineer  
**Последнее обновление:** 2026-08-05

---

# 1. Назначение документа

Настоящий документ определяет последовательность реализации MVP проекта **AI Procurement Auditor**.

Его задача — превратить архитектурную документацию в пошаговый план разработки.

Каждый этап должен завершаться работоспособным результатом, который можно протестировать независимо от последующих этапов.

---

# 2. Цели MVP

Первая версия системы должна обеспечивать полный цикл обработки закупочного документа.

Минимальный функционал MVP включает:

- загрузку документа;
- хранение документа;
- OCR-распознавание;
- извлечение основных реквизитов;
- нормализацию данных;
- выполнение Rule Engine;
- расчет Risk Score;
- формирование отчета;
- ручную проверку при необходимости.

Использование LLM ограничивается только случаями, определенными архитектурой проекта.

---

# 3. Принципы реализации

Разработка выполняется поэтапно.

Каждый этап должен:

- быть завершенным;
- быть протестированным;
- не нарушать предыдущую функциональность;
- иметь понятный критерий готовности.

Переход к следующему этапу допускается только после успешной проверки предыдущего.
---

# 4. Этап 1. Подготовка проекта

Цель этапа — создать основу проекта.

Основные задачи:

- настройка репозитория;
- настройка виртуального окружения;
- установка зависимостей;
- создание Django-проекта;
- создание структуры каталогов;
- настройка Git;
- подготовка архитектурной документации.

### Критерии готовности

- проект запускается локально;
- репозиторий настроен;
- структура каталогов соответствует архитектуре;
- документация создана.

---

# 5. Этап 2. Доменная модель

На данном этапе реализуются:

- модели Django;
- миграции;
- административная панель;
- связи между сущностями;
- начальные справочники.

Основные модели:

- Company;
- User;
- Supplier;
- Document;
- DocumentVersion;
- RuleResult;
- AuditLog.

### Критерии готовности

- все модели созданы;
- миграции выполняются без ошибок;
- объекты доступны через Django Admin.

---

# 6. Этап 3. Загрузка документов

На данном этапе реализуются:

- загрузка файлов;
- проверка формата;
- вычисление SHA-256;
- сохранение файлов;
- создание записи Document.

После загрузки документ получает статус **Uploaded**.

### Критерии готовности

- документ успешно загружается;
- файл сохраняется;
- создается запись в базе данных;
- вычисляется SHA-256.

---

# 7. Этап 4. OCR

На данном этапе подключается OCR Provider.

Pipeline должен:

- отправить документ в OCR;
- получить результат;
- сохранить распознанный текст;
- сохранить Confidence OCR.

### Критерии готовности

- OCR успешно выполняется;
- текст сохраняется;
- возможен повторный просмотр результата без повторного обращения к OCR.
---

# 8. Этап 5. Извлечение и нормализация данных

После получения результата OCR система должна извлечь необходимые реквизиты документа.

На данном этапе реализуются:

- извлечение номера документа;
- извлечение даты;
- извлечение поставщика;
- извлечение ИНН;
- извлечение сумм;
- извлечение НДС;
- нормализация всех значений.

### Критерии готовности

- обязательные поля успешно извлекаются;
- данные сохраняются в базе;
- значения приведены к единому формату.

---

# 9. Этап 6. Rule Engine

После нормализации запускается Rule Engine.

На этапе реализуются:

- загрузка правил;
- последовательное выполнение правил;
- сохранение результатов;
- расчет Risk Score;
- определение итогового статуса документа.

### Критерии готовности

- правила выполняются в правильном порядке;
- результаты сохраняются;
- Risk Score рассчитывается корректно;
- итоговый статус определяется автоматически.

---

# 10. Этап 7. API

После реализации основной бизнес-логики создается REST API.

На данном этапе реализуются:

- JWT-аутентификация;
- API документов;
- API Pipeline;
- API отчетов;
- API аудита.

### Критерии готовности

- все основные эндпоинты доступны;
- авторизация работает;
- ответы соответствуют спецификации API.

---

# 11. Этап 8. Пользовательский интерфейс

Создается первый пользовательский интерфейс на Django Templates.

Реализуются:

- вход пользователя;
- список документов;
- карточка документа;
- загрузка документов;
- просмотр отчета;
- ручная проверка.

### Критерии готовности

- пользователь может пройти полный сценарий работы без использования API напрямую.
---

# 12. Этап 9. Тестирование

После завершения реализации MVP проводится комплексное тестирование системы.

Выполняются:

- модульные тесты;
- интеграционные тесты;
- проверка API;
- проверка Pipeline;
- проверка Rule Engine;
- тестирование пользовательских сценариев.

### Критерии готовности

- успешно проходят все критические тесты;
- отсутствуют блокирующие ошибки;
- подтверждена корректность основных бизнес-сценариев.

---

# 13. Этап 10. Подготовка к пилотной эксплуатации

После завершения тестирования система подготавливается к использованию первыми пользователями.

Выполняются:

- настройка Production-конфигурации;
- настройка резервного копирования;
- настройка мониторинга;
- настройка журналирования;
- проверка безопасности;
- подготовка пользовательской документации.

### Критерии готовности

- система готова к эксплуатации;
- выполнена проверка восстановления резервных копий;
- мониторинг работает;
- журналы аудита сохраняются корректно.

---

# 14. Контрольные точки проекта

По завершении каждого этапа проводится проверка результатов.

Контрольные точки:

- архитектура утверждена;
- модели данных реализованы;
- Pipeline работает;
- Rule Engine функционирует;
- API соответствует спецификации;
- пользовательский интерфейс реализован;
- система успешно проходит тестирование;
- MVP готов к пилотной эксплуатации.

Переход к следующему этапу допускается только после успешного завершения предыдущего.

---

# 15. Definition of Done

План реализации считается завершенным, если определены:

- последовательность этапов разработки;
- цели каждого этапа;
- критерии готовности;
- контрольные точки;
- порядок перехода к следующему этапу.

---

# 16. Завершение архитектурного этапа

После утверждения настоящего документа архитектурное проектирование MVP считается завершенным.

Дальнейшая работа проекта переходит в фазу реализации.
