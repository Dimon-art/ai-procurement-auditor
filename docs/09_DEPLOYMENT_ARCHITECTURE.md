# 1. Назначение документа

Настоящий документ определяет архитектуру развертывания системы **AI Procurement Auditor**.

Цель документа — описать принципы размещения компонентов системы, организацию окружений разработки и эксплуатации, а также требования к надежности, масштабируемости и сопровождению.

Архитектура развертывания должна обеспечивать возможность постепенного перехода от MVP к коммерческой B2B-платформе без изменения основных архитектурных решений.

---

# 2. Цели архитектуры развертывания

Deployment Architecture должна обеспечивать:

- простое локальное развертывание;
- воспроизводимость окружений;
- безопасное хранение данных;
- масштабируемость;
- надежность;
- возможность резервного копирования;
- мониторинг;
- централизованное журналирование.

---

# 3. Окружения системы

Для проекта определяются три основных окружения.

## Development

Используется разработчиками.

Особенности:

- локальный запуск;
- SQLite или PostgreSQL;
- локальное файловое хранилище;
- тестовые API OCR и LLM;
- включенный режим DEBUG.

---

## Staging

Используется для тестирования перед выпуском новой версии.

Особенности:

- конфигурация максимально приближена к Production;
- PostgreSQL;
- отдельное файловое хранилище;
- реальные интеграции OCR и LLM;
- отключенный DEBUG.

---

## Production

Используется конечными пользователями.

Особенности:

- высокая доступность;
- резервное копирование;
- мониторинг;
- журналирование;
- защищенные соединения;
- безопасное хранение секретов.

# 4. Общая схема развертывания

```text
Users
   │
   ▼
HTTPS
   │
   ▼
Reverse Proxy
   │
   ▼
Django Backend
   │
 ┌─┴───────────────┐
 ▼                 ▼
PostgreSQL     File Storage
                  │
          ┌───────┴────────┐
          ▼                ▼
       OCR API         LLM API
```

Backend является центральным компонентом системы и координирует взаимодействие всех остальных компонентов.
---

# 5. Компоненты инфраструктуры

Для MVP используются следующие компоненты.

## Django Backend

Является центральным компонентом системы.

Отвечает за:

- обработку HTTP-запросов;
- выполнение бизнес-логики;
- запуск AI Pipeline;
- работу с базой данных;
- взаимодействие с OCR и LLM.

---

## PostgreSQL

Основная база данных проекта.

Используется для хранения:

- пользователей;
- организаций;
- документов;
- результатов проверки;
- журналов аудита;
- настроек системы.

Все бизнес-данные должны храниться только в PostgreSQL.

---

## File Storage

Файловое хранилище содержит:

- оригиналы документов;
- подготовленные изображения;
- результаты OCR;
- сформированные отчеты.

Файлы не должны храниться внутри базы данных.

---

## OCR Provider

OCR выполняет распознавание текста документа.

Backend взаимодействует с OCR только через Adapter.

Это позволяет заменить поставщика OCR без изменения остальной системы.

---

## LLM Provider

LLM используется только для задач, определенных архитектурой:

- объяснение результатов;
- анализ нестандартных документов;
- AI-чат.

LLM не принимает бизнес-решения вместо Rule Engine.

---

# 6. Управление конфигурацией

Конфигурация приложения должна храниться отдельно от исходного кода.

Для хранения используются:

- `.env` — локальная разработка;
- переменные окружения — Production;
- секреты платформы развертывания.

В репозиторий запрещается добавлять:

- пароли;
- API-ключи;
- токены;
- секретные ключи;
- учетные данные базы данных.
