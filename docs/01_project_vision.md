# 2. Видение продукта

AI Procurement Auditor — SaaS-платформа для автоматической проверки закупочных документов до их оплаты.

Продукт не заменяет ERP, бухгалтерию или электронный документооборот.

Его задача — стать интеллектуальным уровнем контроля между получением документа и финансовым решением.

Система автоматически анализирует документы, выявляет потенциальные ошибки и риски, объясняет причины обнаруженных проблем и передает спорные случаи ответственному сотруднику.

Последнее решение всегда остается за человеком.

---

# 3. Проблема

Во многих компаниях проверка счетов, УПД и накладных выполняется вручную.

Это приводит к следующим рискам:

- повторная оплата одного документа;

- ошибки OCR при ручном вводе;

- расхождения между счетом и договором;

- ошибки поставщика;

- отсутствие обязательных реквизитов;

- человеческий фактор;

- высокая нагрузка на бухгалтерию;

- длительный цикл согласования.

Большинство ошибок обнаруживается уже после оплаты, когда стоимость исправления значительно выше.

---

# 4. Решение

После загрузки документа система автоматически выполняет полный цикл проверки.

Типовой сценарий обработки:

1. загрузка документа;

2. сохранение оригинала;

3. OCR;

4. извлечение реквизитов;

5. нормализация данных;

6. запуск Rule Engine;

7. вычисление Risk Score;

8. формирование объяснений;

9. передача спорных документов человеку.

Если нарушений нет — документ получает статус **Approved**.

Если обнаружены потенциальные проблемы — создается задача на ручную проверку.

---

# 5. Целевая аудитория

Основные пользователи продукта:

- бухгалтерия;

- AP-специалисты;

- финансовые отделы;

- закупочные подразделения;

- внутренний аудит.

В перспективе продукт может использоваться внешними сервисными центрами обработки документов.

---

# 6. Границы MVP

Первая версия должна решать одну задачу максимально качественно:

Проверить загруженный документ до оплаты.

В MVP входят:

- загрузка PDF;

- загрузка сканов;

- загрузка фотографий;

- OCR;

- извлечение основных реквизитов;

- поиск дублей;

- поиск похожих дублей;

- проверка обязательных полей;

- сверка с основанием (при наличии);

- Risk Score;

- очередь ручной проверки;

- журнал действий.

---

# 7. Что НЕ входит в MVP

Следующие возможности сознательно откладываются:

- автоматическая оплата;

- интеграция с банками;

- мобильное приложение;

- сложный антифрод;

- машинное обучение на пользовательских данных;

- многоконтурное согласование;

- микросервисная архитектура;

- Kubernetes.

---

# 8. Основные архитектурные принципы

## 8.1 Человек принимает финансовое решение

AI может рекомендовать.

AI не утверждает оплату.

---

## 8.2 Простые задачи выполняются без LLM

Если правило можно реализовать обычным кодом — используется обычный код.

LLM вызывается только тогда, когда классические алгоритмы недостаточны.

---

## 8.3 Минимизация стоимости обработки

Целевая архитектура:

- 80–90% документов проходят без обращения к LLM;

- LLM используется только для сложных случаев;

- стоимость обработки одного документа должна быть минимальной.

---

## 8.4 Explainable AI

Каждое предупреждение должно сопровождаться объяснением:

- что обнаружено;

- почему это считается риском;

- какие данные использовались;

- что рекомендуется сделать.

---

## 8.5 Audit First

Любое действие пользователя и системы фиксируется.

История изменений документа должна быть полностью воспроизводимой.

---

## 8.6 Простота архитектуры

До подтверждения продуктовой гипотезы запрещается усложнять систему.

Не используются:

- микросервисы;

- Kubernetes;

- распределенные очереди;

- собственные OCR-модели;

- собственные LLM.

---

# 9. Ключевые нефункциональные требования

Система должна быть:

- простой для сопровождения;

- понятной Junior-разработчику;

- легко расширяемой;

- безопасной;

- масштабируемой;

- пригодной для коммерческой эксплуатации.

---

# 10. Критерии успешного MVP

Первая версия считается успешной, если позволяет:

- загрузить документ;

- автоматически извлечь основные реквизиты;

- выполнить проверки;

- показать найденные проблемы;

- объяснить результаты проверки;

- направить документ на ручную обработку.
