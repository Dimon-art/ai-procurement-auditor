# 1. Назначение документа

Настоящий документ определяет спецификацию Rule Engine системы **AI Procurement Auditor**.

Rule Engine является центральным механизмом принятия бизнес-решений.

Все проверки документов выполняются правилами (Rules), работающими независимо друг от друга.

Результаты работы Rule Engine используются для расчета Risk Score, формирования отчета и принятия окончательного решения по документу.

---

# 2. Цели Rule Engine

Rule Engine должен обеспечивать:

- выполнение независимых бизнес-проверок;
- повторяемость результатов;
- расширяемость без изменения существующих правил;
- минимальное использование LLM;
- прозрачность принятия решений;
- формирование объяснений для пользователя.

Все правила должны работать детерминированно.

---

# 3. Основные принципы

При разработке Rule Engine используются следующие принципы.

## 3.1 Независимость правил

Каждое правило выполняется независимо от остальных.

Ошибка одного правила не должна останавливать выполнение остальных.

---

## 3.2 Детерминированность

При одинаковых входных данных правило всегда должно возвращать одинаковый результат.

---

## 3.3 Расширяемость

Добавление нового правила не должно требовать изменения существующих правил.

Каждое правило реализуется как самостоятельный компонент.

---

## 3.4 Объяснимость

Каждое срабатывание правила должно содержать:

- название правила;
- результат проверки;
- уровень серьезности;
- понятное объяснение причины.
---

# 4. Жизненный цикл Rule Engine

После завершения этапов OCR и нормализации данных Pipeline запускает Rule Engine.

Последовательность выполнения:

```text
Normalized Document
        │
        ▼
Load Rules
        │
        ▼
Execute Rules
        │
        ▼
Collect Results
        │
        ▼
Calculate Risk Score
        │
        ▼
Generate Final Decision
```

Каждое правило получает одинаковый объект документа и возвращает стандартизированный результат.

---

# 5. Структура правила

Каждое правило должно содержать:

- уникальный идентификатор;
- название;
- описание;
- уровень серьезности;
- вес правила;
- входные данные;
- результат проверки;
- объяснение.

Пример структуры:

```text
Rule ID
Rule Name
Severity
Weight
Status
Message
```

Это обеспечивает единообразную обработку результатов всеми компонентами системы.

---

# 6. Категории правил

Все правила делятся на несколько категорий.

## Document Rules

Проверяют сам документ.

Примеры:

- корректность формата;
- обязательные реквизиты;
- качество OCR.

---

## Supplier Rules

Проверяют поставщика.

Примеры:

- наличие в справочнике;
- корректность ИНН;
- соответствие организации.

---

## Financial Rules

Проверяют финансовые данные.

Примеры:

- итоговую сумму;
- сумму НДС;
- соответствие связанных документов.

---

## Duplicate Rules

Проверяют наличие повторяющихся документов.

---

## Consistency Rules

Проверяют согласованность информации между различными реквизитами документа.

---

# 7. Результат выполнения правила

Каждое правило возвращает единый объект результата.

Минимальный состав:

- Rule ID;
- Rule Name;
- Status;
- Severity;
- Weight;
- Message;
- Details.

Все результаты собираются Rule Engine и используются при расчете итоговой оценки риска.
