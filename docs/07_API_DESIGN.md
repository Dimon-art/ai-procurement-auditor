# 1. Назначение документа

Настоящий документ определяет архитектуру REST API системы **AI Procurement Auditor**.

API является единственной точкой взаимодействия между Backend и внешними клиентами.

Все операции выполняются через HTTP API.

Backend не предоставляет прямой доступ к базе данных.

---

# 2. Цели API

REST API должно обеспечивать:

- аутентификацию пользователей;
- управление организациями;
- загрузку документов;
- просмотр документов;
- запуск обработки;
- получение результатов проверки;
- просмотр отчётов;
- получение журналов аудита.

API проектируется независимо от пользовательского интерфейса.

Это позволяет использовать:

- Web Frontend;
- Mobile Client;
- внешние корпоративные системы;
- интеграции через API.

---

# 3. Архитектурные принципы

REST API строится на следующих принципах.

## 3.1 Stateless

Каждый HTTP-запрос содержит всю информацию, необходимую для его обработки.

Сервер не хранит состояние клиента между запросами.

---

## 3.2 JSON

Все запросы и ответы используют формат JSON.

---

## 3.3 Versioning

Все URL содержат номер версии API.

Пример:

```text
/api/v1/
```

Это позволит развивать API без нарушения обратной совместимости.

---

## 3.4 Единый формат ответов

Все ответы API используют одинаковую структуру независимо от типа запроса.

Это упрощает разработку Frontend и интеграций.
